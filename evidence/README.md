**Same model, same wrapper.** Every skill arm is one fresh `claude -p --model sonnet` call (Claude Sonnet 5.5), run from an empty directory with all user settings, tools and project instructions disabled. ## Inputs

- **16 main texts** in the genres people actually clean up: LinkedIn post, cold email, release notes, newsletter intro, PRD section, landing page, Slack update, blog paragraph, support reply, pricing-change email, job post, talk abstract and bio, strategy memo, X thread, app store description, personal reflection.
- **How they were made, so they are not a strawman.** One model call wrote 16 fictional writer briefs (`inputs/briefs.json`): the short request a busy person would type, and 6-10 hidden facts they know but did not type. A fresh call that saw only the request wrote each draft, asked to write normally. 8 drafts came from Claude Sonnet and 8 from OpenAI's model through the Codex CLI, so the rewriting model is not only editing its own family's prose. Nobody edited them.
- **8 held-out texts** (`holdout/`), new writers, industries and genres, generated the same way after v3 was frozen. No version was tuned on them.
- **Track 3 human texts**: 4 excerpts (290-340 words each) of the skill author's own writing, published in 2022 before ChatGPT's release. They and every text derived from them are not included; only aggregate numbers are. To rerun Track 3, bring your own (`scripts/run_track3.py`).

## Measures

1. **Blind judges**: first Codex CLI (OpenAI, high reasoning effort) and Claude Opus; then a five-family panel re-judged everything (see Five-judge panel). Arm labels stripped, candidates shuffled, every text judged in 2 random orders per judge (3 on the held-out set). Two questions, asked separately: rank by "how much each reads like a skilled human wrote it for this purpose" (with the unedited draft hidden among the candidates) plus "which one would you send"; and, with the original shown, rank by "how faithfully each keeps the original's meaning, facts, numbers, commitments and caveats". Reported as win-tie-loss per text and judge, pooled across both judges.
2. **Fact check**: one Opus call per pair lists dropped, changed and added facts, and invented specifics. Every invented-specific or major finding was then checked by hand against the texts (`scores/factcheck_verified.md`).
3. **Pangram** (Pangram 4, API): fraction of the text called human, AI, or AI-assisted, and the label. 197 texts, one call each (175 for the comparison, 22 more for the detector exploration).
4. **Local open-source detectors**, calibrated before use (see Detectors).

## v5: the published version, and the gap to the bare prompt

**Why the panel preferred the bare prompt over v3** (96 judgments on 24 texts): on the 4 texts where it invented facts it won by a net 2.75 judgments per text, elsewhere by 0.9 per text, so invention explains about 38% of its margin. In the judges' own written reasons, when it won the cause was its conversational register (48 of 57: contractions, first person, direct address, everyday verbs, warmth), a freshly written feel versus "a lightly edited AI draft" (25), v3 being flat or over-trimmed (19), v3 keeping template labels (18), filler (15), and invented detail (5). Measured: it rewrote 76% of the draft's 4-word sequences (v3: 36%) and used more contractions. When v3 won, the bare prompt's casual touches read as forced (19 of 28).

**v5 changes** (from v3): write the piece fresh from the fact list in the writer's voice, same claims at the same strength; keep the claim and drop the formula for stock lines; cut tells without clipping (about as long as an unpadded draft); concrete register defaults (contractions, the speaker as themselves, "you", everyday verbs, ownership, plain warmth, conversational not colloquial); uninformative labels become sentences; a fact audit that checks strength words. Three dev rounds on the 16 test texts (Codex + DeepSeek); v3, v5 round 1 and round 2 are in `skill-versions/`.

- An assistant model rewriting AI text leaves Pangram's verdict where it was. This matches an earlier five-cell test by the same author on a human-written article: AI formatting, an AI copyedit and a full AI rephrase all stayed 99-100% human, AI composition from the outline scored 68%, and a style-targeted rewrite of that version moved it one point. The score follows who composed the sentences.
- Emulate-1 changes the verdict without human material. Pangram's own humanizer flag (`is_humanized` in its response) fired on 1 of the 35 Emulate texts.
- Raw responses (no text) in `scores/pangram/`, the call log with credits in `scores/pangram_log.csv` (one manual test call and one call that timed out are counted in the spend and excluded from results).

## Local open-source detectors (secondary)

Calibrated on 10 pre-ChatGPT human excerpts vs 24 AI drafts: desklib/ai-text-detector-v1.01 separated them (AUROC 0.90, no human text flagged); fakespot-ai/roberta-base-ai-text-detection-v1 (0.73) and TrustSafeAI/RADAR-Vicuna-7B (0.66) flagged too few AI drafts to use. On Track 1, desklib flagged the drafts 9 of 16 and every rewrite arm 10-11 of 16; Emulate's rewrites 8 of 15. On Track 3 its score had no relationship with how much of the text was human-composed (Spearman -0.09) and it disagreed with Pangram on most human-material variants. It reacts to surface style, not composition. Data: `scores/detectors.csv` (calibration texts listed only as `human-NN`).

An in-house heuristic AI-tell scorer (em dashes, transition words, sentence-length band, specificity) was also run. It could not separate any arms: the 2026 drafts already contained almost none of the tells it counts. It is not included.

## Where blader/humanizer does better

- **Reading human, slightly**, against work-humanizer v3 (not significant). Its rewrites were also judged more human than v2's.
- **Keeping the meaning against work-humanizer v1** (18-2-12 for blader): v1's "state facts flat" rule stripped qualifiers the writer chose ("could help reduce" became "cuts"). blader's explicit check ("did the rewrite add or drop any fact, name, number, date, quote, citation, ranking...") avoids that by construction. v2 and v3 fixed it with a "What you must not change" section.
- **Templated structure in documents.** In the strategy memo, blader turned repeated "Mitigation:" labels into plain sentences and both judges preferred its version; work-humanizer kept the labels (see `../examples/`).
- **When the user explicitly asks to be interviewed**, both skills ask, and the judges slightly preferred blader's results (5-3, 4 texts).

## Versions

- **v1**: tied blader on reads-human, lost on meaning (12-2-18).
- **v2**: added "What you must not change" (certainty, reasons, vague-into-vaguer, actor), "Sound like a person, not a costume", the count-before-a-list tell, and the new interview trigger. Meaning flipped to 27-2-3; reads-human dropped to 9-5-18 because "edit in proportion" left tells in place.
- **v3** (published first, now `skill-versions/v3/`): every tell gets fixed even in a sentence that sounds fine; certainty kept at the level, not the exact words. Meaning 25-1-6, reads-human back to a tie, confirmed on the held-out set.
- **v4 (tried, not adopted)**: a second pass for surviving tells, a two-way fact audit, uninformative labels to prose (principles also present in blader/humanizer, written in our own words), 14 reviewer patterns mined from judge comments, and a blind self-review step. On reads-human it stayed level with v3 (32-2-30 head to head); on meaning the judges preferred v3 (37 to 23). work-humanizer stays on v3.
- **`check.py` fix after the run**: the bold-label pattern now also catches `**Label.**` with the period inside the bold (found by the unit tests). `check.py` was not available to any arm during the test, so no result depends on it.
- **Wording edits after the run, no instruction changed**: the final check names the dash characters by code point; the specificity line says "density of numbers, names, and dates" (what the cited study measured); the detector paragraph now states the Pangram result above instead of "rewording cannot change who composed the sentences", which Emulate disproved.
- **Two edits after all measurements (2026-10-09), not re-measured**: (1) when writing from the writer's notes, the fact audit runs against the notes, and facts found only in an AI draft become optional; (2) final check 7: for pieces over about 100 words the skill ends with a "Shorter option:" line, either cuts it would offer (up to about half: an opening the piece doesn't need, lines any similar piece would have, near-duplicates, a second argument that could move to a reply) or "none", and never applies them. Calibrated in 5 rounds on 13 texts (Sonnet, plus Opus spot checks): short texts were skipped every time; on one clearly padded post the option fired in 3 of 5 runs, each about a third, never proposing to cut examples, numbers or a disclosure after round 1; moderately padded drafts got "none" (cuts under a quarter after the rewrite's own trimming). Rewrite mode, which every scoreboard number measures, and interview mode are unchanged by (1); (2) adds text only after the final text, and only the final text was ever scored. The notes-route numbers (4 texts) were measured before (1).

## Caveats

- Small samples: 16 + 8 texts, 4 human excerpts in Track 3, one generation per text per arm. Treat every result as directional; p-values are sign tests per judge.
- Judges are models, not people, and they disagree with each other. No human readers were used.
- All skill arms ran on one model (Claude Sonnet 5.5). Results on other models may differ.
- The interview track uses a simulated writer; its answers are model-written. Track 3 uses real human words but only one author's.
- Pangram: one model version, one day. Detectors change.
- The people who wrote work-humanizer designed the test. Mitigations: a held-out set, judges from two model families, the original hidden among candidates, every hard fact finding checked by hand, and blader's skill run unmodified at a pinned commit.

Emulate-1: 6,574 words. Pangram: about 475 credits including the detector set. Five-judge panel: $10.30 on OpenRouter plus Codex and Opus on subscriptions. Decision models: $0.06. ## Reproduce

Requirements: Python 3.11+, the `claude` CLI (Claude Code) logged in, the `codex` CLI logged in. Optional: `PANGRAM_API_KEY` and `EMULATE_API_KEY` environment variables; `torch` and `transformers` for the local detectors.

```bash
cd evidence
python scripts/fetch_blader.py                 # arm A's skill text, pinned commit
python scripts/run_track1.py A B B2 B3 C       # skips outputs that already exist; delete outputs/ to regenerate
python scripts/factcheck.py A B B2 B3 C
python scripts/judge.py t1v3 O,A,B,B3,C --meaning && python scripts/analyze_judges.py t1v3 "B3:A,B3:C,A:C"
HUMANIZER_SET=holdout python scripts/run_track1.py A B B2 B3 C   # the held-out set
python scripts/run_track2.py A B2 && python scripts/track_measures.py t2 A-int B2-int
python scripts/run_track3.py                   # needs your own pre-2023 texts in evidence/human/
python scripts/pangram_run.py --estimate       # then --run; hard cap inside the script
python scripts/run_emulate.py --estimate       # then --run; --write for the writing track
python scripts/detect.py && python scripts/detector_summary.py
```

`scripts/gen_inputs.py` regenerates briefs and drafts (`briefs`, `drafts`, and `briefs-holdout` with `HUMANIZER_SET=holdout`).

## Layout

```
inputs/              briefs.json (requests + hidden facts), manifest.json (which model wrote each draft), the 16 drafts
outputs/<arm>/       final texts per arm (E/raw/ has Emulate's response metadata)
holdout/             the 8 held-out drafts, outputs and scores
holdout2/            the 8 new fresh drafts (generated after every version was frozen), blader, v3 and v5 outputs, scores
holdout3/            the 12 final validation drafts, every arm's output, fact checks and verdicts
holdout5/            the 12 scoreboard drafts, every arm's output (V6A = one-liner, V6C = v6), fact checks, verdicts, summary.json
track2/<arm>-int/    interview-mode finals; raw/ has questions, simulated answers and replies
gen/E-write/         Emulate-1 writing from the requests
skill-versions/      work-humanizer v1 and v2 as tested
scores/              judges/ (every verdict), factcheck/, gen_check/, track2/, pangram/ and their summaries
scripts/             everything above, rerunnable
```

Judging passes: `t1` (v1, blader, bare prompt), `t1v2` and `t1v3` (adds each version), `ho` (held-out, all versions), `t2` (interview), `t1e` and `gen` (Emulate), `t3r`, `t3m`, `t3e` (Track 3, aggregates only), `panel` (five judge families, all three sets).
